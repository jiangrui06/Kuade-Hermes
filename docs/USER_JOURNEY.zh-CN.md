# Kuade 0.2.3 用户完整流程验收

默认简体中文。[繁體中文](USER_JOURNEY.zh-TW.md) · [English](USER_JOURNEY.en.md)

## 本轮改善

- 回复中的行内代码形式网址现在也能点击打开；普通命令和多行代码块保持原样。

- 新建任务页面明确显示当前项目，避免选了项目却仍被提示使用默认工作区。
- 「代码变更」把文件列表放在预览旁边，点击文件名即可检查单个文件的 Diff。
- 新增文件也可以直接预览，不再只有文件名；显示空文件、二进制、编码和大文件提示。
- 提供「回到任务继续修改」，保留原任务上下文。
- 普通文件夹尚未启用 Git 时，解释原因和下一步，不直接展示底层命令错误。

查看内容是只读操作。恢复修改仍需明确确认，并检查原始 Diff 是否已经变化；新增文件没有删除或恢复按钮。文件预览使用现有 Git 与文件系统接口。网址识别复用 [linkify-it 6.1.0](https://github.com/markdown-it/linkify-it)（MIT），兼容紧邻中文的地址；执行引擎保持不变。

## 真实模型用户流程

通过隔离的 Windows 桌面配置使用用户已保存的 Kimi K3 连接；模型响应没有替换成测试桩。测试代码只创建报价计算器的初始项目，不编写优惠和重置功能的实现。

1. 点击打开项目、新建任务，选择模型和自动执行模式。
2. 让模型添加优惠计算、输入校验、测试和说明文档。
3. 查看代码修改；改进后的版本还检查新增文档预览与逐文件 Diff。
4. 在任务记录中重命名、搜索、重新打开，要求模型继续添加重置按钮。
5. 独立检查计算逻辑、非法输入与生成的测试，并在真实 Edge 浏览器检查优惠结果与重置操作。
6. 重启桌面端，确认任务名、上下文和回复仍可打开。

初轮模型曾建议直接双击使用 ES module 的 HTML；后续流程明确反馈这个问题，要求通过本地 HTTP 服务访问。模型说明与实际测试结果分别核对。

## 证据与范围

机器可读结果：`docs/acceptance/real-user-journey-0.2.3-2026-10-22.json`。记录包含初轮、修复后的实际版本、测试数量、截图与原始证据路径。

文件夹选择器仅由测试提供确定路径，后续项目打开和任务操作使用真实界面。预览应用通过隔离的本地 HTTP 服务在 Edge 中运行，不把系统默认浏览器启动计为通过。本轮是报价计算器的两轮任务与持久化验收，不替代大型项目、跨天任务、电脑控制或自更新专项验收。

仅复制模型配置与凭据到隔离配置目录；测试结束删除这些临时文件，并通过哈希检查原配置未变。证据中不记录密钥。Windows 交付使用便携 ZIP，未重新生成安装器。

## 本轮结果

142 项应用测试、22 项验收脚本测试、类型检查、生产构建和桌面交互检查通过。最近一次完整的两轮真实 Kimi K3 开发在 0.2.2 通过；交付版本 0.2.3 进一步修正网址识别，使用同一真实任务回放复验，没有再次发送开发请求。生成项目的 12 项测试再次通过，Edge 中的优惠合计为 53.97，重置后为 100.00。

最终版也验证了新文件预览、逐文件 Diff、窄窗口、返回任务，以及重启后继续输入。网址点击验证包含主进程分发，系统浏览器打开器由测试替身接收；真实页面功能另在 Edge 验证。
