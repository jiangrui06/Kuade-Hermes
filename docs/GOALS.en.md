Expand “设置持续目标” above the composer, enter an objective and automatic round limit, then click “开始持续目标”. Goals use the current workspace, model and execution mode. Ordinary messages remain ordinary conversation turns. The default limit is 256 automatic rounds; a round may contain multiple model requests. This is not a cost or elapsed-time budget.

Harness starts another round while a goal is active and armed. “暂停目标” stops the current round and pauses continuation. Exiting preserves the goal and session but stops running processes. Reopen the task and click “恢复目标” to inspect existing files and continue remaining work. Restarting does not revive interrupted commands. Reaching the round limit stops continuation; arrange further work in a new task.

“Agent 报告目标完成” identifies a model-reported state, which still needs independent file and test verification. Long objectives scroll and support keyboard focus and paging. Background execution consumes provider quota; manual sleep, network loss and shutdown affect execution.

## Module boundaries

Persistence, continuation and state transitions reuse goal and goal-round-driver from pinned Harness 0.2.0-rc.2. GoalPanel displays state and invokes allowlisted `goals/get`, `goals/create`, `goals/pause`, `goals/resume`; creation shares existing session and model preparation. Pause/resume carry the goal ID and revision to avoid overwriting changed state. No additional Agent loop, goal database or dependency was introduced.

## Reproduction

After building, run `npx playwright test tests/e2e/goals.spec.ts`. For the real provider, explicitly set `KUADE_REAL_RECOVERY=1` and `KUADE_MODEL_PROFILE` (a Kuade profile with a saved model connection), then run `scripts/accept-real-recovery.mjs`. Set `KUADE_RECOVERY_GOAL=1` for ongoing-goal mode. The script uses an isolated profile and temporary workspace, removes copied model credentials on exit and leaves the user's running instance open. It consumes provider quota and writes receipts under `D:/Kuade-acceptance`.
